# Установщик и дальнейшие обновления

Нативная оболочка: `io.github.troglobiont.trailclients`, runtime 1, минимальная совместимая нативная версия 0.1.1. Используется тот же способ ручного обновления интерфейса, что в операторе 38: [CapacitorUpdater manual download/set](https://capgo.app/docs/plugins/updater/api/), подтверждение `notifyAppReady` и откат при неудаче.

## Один раз на телефоне

Репозиторий закрытый. В GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens создать токен только для `troglobiont/the-trail-clients`, Repository permissions → Contents → Read-only. Указать ограниченный срок действия. Вставить его в приложении: «Настройки → Данные и обновления → Доступ к обновлениям». Ключ шифруется Android Keystore; в исходниках и экспорте его нет. После истечения срока заменить ключ.

Для настройки не нужен токен с правом записи, доступ ко всем репозиториям или личный токен в файлах приложения. Если доступ не настроен, «Обновить сейчас» покажет причину; рабочая версия и база останутся на устройстве.

## Обычное обновление интерфейса

1. Изменить `src/`, поднять semver в корневом package.json. Для изменений только интерфейса нативные versionCode/versionName не поднимать.
2. Проверить тесты, сборку и `scripts/check.mjs`. В `dist/` не должно быть клиентской базы и ключей.
3. Обновить `docs/release-notes.md`, отправить изменения в main. Workflow собирает Android и детерминированный ZIP, затем публикует release `vX.Y.Z` с `THE-TRAIL-Clients-update.zip`, `version.json` и SHA256SUMS.
4. Не заменять архив уже выпущенной версии другим содержимым. Исправление выпускается новым номером версии.
5. В установленном приложении нажать «Обновить сейчас». Проверить сохранность клиента, незавершённой задачи и черновика.

Чтение закрытого выпуска идёт через API с ключом; загрузка архива — по выданной GitHub временной HTTPS-ссылке. Токен не передаётся CDN. Манифест разрешает только точное имя пакета и release этого репозитория. SHA-256 сверяется плагином перед применением; отдельная проверка результата также исключает явное несовпадение.

## Новый APK

Нативные изменения требуют увеличения `mobile/android/app/build.gradle` → versionCode/versionName, а при несовместимости — повышения runtime и минимальной нативной версии в сборщике обновлений и мосте. Нативную сборку сначала проверить отдельно, затем выпускать совместимые пакеты.

Workflow выдаёт `android-unsigned-for-local-signing`. Скачать его, подписать локальным постоянным ключом и проверить через `apksigner verify --verbose --print-certs`. Секрет и пароль не выводить в лог и не добавлять в репозиторий/CI. Публиковать только проверенный подписанный файл под именем `THE-TRAIL-Clients-Android.apk` в соответствующий release.

Следующий APK подписывается тем же ключом и ставится поверх. Пользовательскую базу не включать в APK. Не удалять приложение перед обновлением.
