# Установщик и дальнейшие обновления

Нативная оболочка: `io.github.troglobiont.trailclients`, runtime 1, минимальная совместимая нативная версия 0.1.10. Для обновления интерфейса используется [CapacitorUpdater manual download/set](https://capgo.app/docs/plugins/updater/api/), подтверждение `notifyAppReady` и откат при неудаче.

## На телефоне

Репозиторий публичный. Скачать подписанный `THE-TRAIL-Clients-Android.apk` из Releases, установить и импортировать отдельно переданную личную базу. Для скачивания и кнопки «Обновить сейчас» вход в GitHub и токен не требуются.

Если установленная версия до 0.1.15 получает ошибку лимита GitHub, подписанный APK 0.1.15 можно скачать по прямой ссылке в Releases и установить поверх приложения.

Клиентская база, заметки и ключ подписи не публикуются. Открытый канал содержит только исходники и общие установочные пакеты.

## Обычное обновление интерфейса

1. Изменить `src/`, поднять semver в корневом package.json. Для изменений только интерфейса нативные versionCode/versionName не поднимать.
2. Проверить тесты, сборку и `scripts/check.mjs`. В `dist/` не должно быть клиентской базы и ключей.
3. Обновить `docs/release-notes.md`, отправить изменения в main. Workflow собирает Android и детерминированный ZIP, затем публикует release `vX.Y.Z` с `THE-TRAIL-Clients-update.zip`, `version.json` и SHA256SUMS.
4. Не заменять архив уже выпущенной версии другим содержимым. Исправление выпускается новым номером версии.
5. В установленном приложении нажать «Обновить сейчас». Проверить сохранность клиента, незавершённой задачи и черновика.

Начиная с интерфейса 0.1.15 приложение читает манифест из `releases/latest/download/version.json` и загружает архив с версионной ссылки. Запросы GitHub REST API и токен для этого маршрута не используются. Манифест разрешает только точное имя пакета и release этого репозитория. SHA-256 сверяется плагином перед применением; отдельная проверка результата также исключает явное несовпадение.

## Новый APK

Нативные изменения требуют увеличения `mobile/android/app/build.gradle` → versionCode/versionName, а при несовместимости — повышения runtime и минимальной нативной версии в сборщике обновлений и мосте. Нативную сборку сначала проверить отдельно, затем выпускать совместимые пакеты.

Workflow выдаёт `android-unsigned-for-local-signing`. Скачать его, подписать локальным постоянным ключом и проверить через `apksigner verify --verbose --print-certs`. Секрет и пароль не выводить в лог и не добавлять в репозиторий/CI. Публиковать только проверенный подписанный файл под именем `THE-TRAIL-Clients-Android.apk` в соответствующий release.

Следующий APK подписывается тем же ключом и ставится поверх. Пользовательскую базу не включать в APK. Не удалять приложение перед обновлением.

## Личный APK с начальной базой

Начиная с нативной версии 0.1.3, после CI-сборки локально можно добавить в неподписанный APK asset `assets/trail-initial.client-data.json`, затем подписать постоянным ключом. Формат — обычная резервная копия с дополнительным `initialDatasetId`. Этот файл не добавлять в Git, CI, общий ZIP обновлений или публичные Releases.

При запуске база проверяется и объединяется с локальной: существующие сущности и настройки сохраняются. Маркер применения сохраняется атомарно вместе с базой. Повторный запуск и обновление интерфейса не применяют этот набор заново. Публичный APK без asset работает как прежде. Ошибка чтения существующей базы не должна приводить к её замене начальной базой.

## Исправление Android-моста в 0.1.6

В оболочках до 0.1.6 метод resolveAsset использовал PluginCall.getLong, который отклоняет JSON Integer. Для исправления требуется APK 0.1.6/versionCode 5; обновление JavaScript не заменяет установленный Java-код. Новые манифесты указывают minNativeVersion 0.1.6. UpdateAssetId принимает только положительный целочисленный Number в безопасном диапазоне JavaScript. Регрессионный Java-тест запускается до сборки APK в CI.
