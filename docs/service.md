# Личный сервис агента и Telegram

Сервис подготовлен в `server/`, но автоматически нигде не размещается. Для подключения нужен собственный постоянно доступный HTTPS-адрес и доступы владельца. Без них локальная база, задачи и цели работают; AI-разбор и отправка не имитируются.

## Запуск

Python 3.11+. Создать приватный каталог данных и переменные окружения по `server/.env.example`. Значения задаются в окружении процесса; `.env` автоматически не читается. `TRAIL_SERVICE_TOKEN` — случайная строка не короче 24 символов. `OPENAI_API_KEY` и `OPENAI_MODEL` задаются владельцем для своего API-проекта. Модель должна поддерживать Responses и Structured Outputs; приложение не навязывает оплачиваемую модель без настройки.

```sh
python3 -m server.service
```

По умолчанию сервер слушает только 127.0.0.1:8787. Разместить за своим HTTPS reverse proxy, ограничить доступ к каталогу `server/data`, настроить его резервное копирование. Открывать напрямую HTTP-порт в интернет не нужно. В приложении указать HTTPS origin и `TRAIL_SERVICE_TOKEN`; ключ попадёт в Android Keystore. Подключение передаёт выбранную запись и контекст одного клиента, а не всю базу.

## Обработка записей

`POST /records/parse` принимает исходную запись, карточку, существующие цели и открытые задачи. [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) возвращает ограниченные операции: цель, задача или особенность. Сервер и приложение проверяют результат. ID цели должен принадлежать этому клиенту. Запись и результат обработки имеют устойчивые ID; повтор не создаёт дубль. Неопределённый результат возвращает короткий вопрос, не исполняя изменения.

У сервиса нет инструмента самостоятельной отправки сообщения из результата модели. Он не назначает тренировки, не подтверждает оплату, не ставит диагноз и не закрывает задачи по догадке. В запросе Responses установлен `store: false`; это не заменяет проверку политики обработки данных своего API-проекта.

`POST /audio/transcribe` принимает запись до 6 МБ, использует [Audio Transcriptions](https://developers.openai.com/api/docs/guides/speech-to-text), возвращает текст в тот же черновик. Модель расшифровки задаётся `OPENAI_TRANSCRIBE_MODEL`. Аудио не сохраняется сервисом в файл. Android запрашивает разрешение на микрофон по нажатию «Надиктовать».

## Telegram от личного аккаунта

Установить `server/requirements.txt`, задать собственные `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` и приватный путь `TELEGRAM_SESSION`. Один раз выполнить интерактивно:

```sh
python3 -m pip install -r server/requirements.txt
python3 -m server.telegram_login
```

Авторизоваться локально на сервере. OTP, пароль и session-файл не передаются в чат, репозиторий или APK. После подключения нажать «Проверить подключение Telegram» в настройках. В карточке — «Привязать переписку», найти контакт по имени или точному @username, проверить получателя и сохранить. Привязка не отправляет сообщение. `/telegram/status` и `/telegram/search` требуют тот же ключ сервиса; поиск возвращает только имя, username и ID, максимум 10 результатов. Группы, боты и собственный аккаунт не предлагаются как получатели.

`POST /telegram/send` принимает только одну из трёх заготовок и положительный ID личного получателя. Отправка выполняется пользовательским аккаунтом, а не отдельным ботом. Точный запрос повторяется с тем же `random_id`; подтверждение сохраняется в SQLite. [Telegram описывает random_id как защиту от повторной отправки](https://core.telegram.org/method/messages.sendMessage). Telegram-сессия должна быть личной и авторизованной заранее; сервер не запускает интерактивный вход при API-запросе.

Автоматическая синхронизация входящих сообщений, общая серверная клиентская база и связь именно с текущим desktop-чатом не реализованы этим сервисом. Он предоставляет обработку выбранной записи и явную отправку; приложение остаётся локальным источником клиентской базы первой версии.

## Бесплатный тест на Mac

Создать отдельное Python-окружение, установить requirements.txt. Приватная JSON-конфигурация вне Git содержит переменные из .env.example. Для скрытого локального ввода и авторизации: `python -m server.mac_login /absolute/private/service-config.json`. Номер, код и пароль не вводить в чат. Сервис: `python -m server.mac_service /absolute/private/service-config.json`.

Сервис слушает только 127.0.0.1. Для теста использовать официальный cloudflared Quick Tunnel к локальному порту. Все операции с клиентами и Telegram требуют Bearer-ключ; `/health` не содержит личных данных. Mac и tunnel должны работать; после остановки и нового запуска Quick Tunnel адрес меняется. Это тестовый канал без гарантии доступности. При включении Telegram оставить AI-разбор выключенным, если OpenAI ещё не настроен.

В интерфейсе 0.1.5 добавлен ввод кода подключения: JSON с format=the-trail-connection-v1, serviceURL (только HTTPS origin) и key. Его можно показать на Mac локальным QR и распознать обычной камерой телефона. Код не публикуется в GitHub и не отправляется в чат. В приложении: Настройки → Агент и Telegram → Подключить с Mac → вставить код → Применить подключение. Дальше проверить отображаемый аккаунт и явно выбрать Telegram-контакт в карточке.
